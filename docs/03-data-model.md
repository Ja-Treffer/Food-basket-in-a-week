# 03 · 数据模型：四个 JSON 的字段字典

四份数据，两份是手写的、两份是生成的。

| 文件 | 手写/生成 | 谁读它 |
|---|---|---|
| `src/game.template.html` | 手写 | 人；再由脚本抽出下面两份 |
| `data/game-i18n.json` | 手写（由翻译合并而来） | `patch_game_i18n.cjs`、`I18nBox`、`review.html` 之外的三个页面 |
| `godot/data/game.json` | 生成 | `TradeoffSession` |
| `data/quiz.json` | 生成 | `live/server.mjs`、`check_review` 对照 |

---

## 1. `godot/data/game.json`

顶层五个键：

```json
{ "v": 1, "cfg": {...}, "refs": {...}, "tasks": [...], "long": [...], "events": [...] }
```

### `cfg` — 全局参数

| 字段 | 值 | 含义 |
|---|---|---|
| `days` | 7 | 一局几天 |
| `tasksPerDay` | 2 | 每天几件事 |
| `start` | `{p:68, s:58, c:62, m:55}` | 四条读数起值（练习 `_start_` 那套） |
| `burnBelow` | 25 | 口味跌破这条线 ⇒ 崩盘 |
| `burnMax` | 2 | 一局最多崩几次 |
| `burnRecover` | 32 | 崩盘后口味拉回到哪 |
| `burnGiveback` | 0.55 | 回吐最近 3 笔环境改善的比例 |
| `rebound` | `{rate:0.8, saleBonus:0.2, cap:16, saveShare:0.6}` | 省下的钱回流（末日 ×0.8、遇促销 +0.2、上限 16、只算 60%） |
| `advocacy` | `{base:0.35, high:0.15, low:-0.15, policy:0.2, win:[8,14], highAt:60, lowAt:25}` | 向学校提议的成功率与收益 |
| `timeBudget` | 300 | 课堂硬上限（秒） |

### `tasks[]` — 普通任务（8 个）

```json
{
  "id": "t1",
  "place": "home",            // home | market | lab | fabric
  "npc": "母亲",               // 同时决定立绘配色
  "theme": "校服脱线，明日要穿",
  "say": "「裤脚脱线，明日要穿；或者干脆做一条新围裙。」",
  "steps": [ { "q": "主料怎么选？", "opts": [ ... ] } ]
}
```

### `long[]` — 中期任务（6 个，L1–L6）

形状与 `tasks` 完全一致，只是 `steps` 恒为 1 步，选项里带 `delay`：

```json
{ "text": "报名，买两个小桶分干湿", "fx": {...}, "delay": { "after": 2 }, ... }
```

`after: N` = 从今天起第 N 天到账；也支持绝对写法 `{ "day": 5 }`，两者都会被 `mini(days, at)` 封顶。

### `events[]` — 每日情景（先于任务结算）

```json
{ "npc": "天文台", "text": "酷热天气警告生效…", "fx": {"c": [-5,-2]}, "ref": ["R6"], "why": "…" }
```

### `opts[]` — 一个选项

| 字段 | 类型 | 说明 |
|---|---|---|
| `text` | string | 选项正文（**键是 `text` 不是 `t`**，写错就出现只有 A/B/C 的空按钮） |
| `fx` | `{p:[min,max], s:[…], c:[…], m:[…]}` | 模糊区间，结账时在区间内均匀抽整数；缺哪个轴就是 0 |
| `ref` | string[] | 依据编号，结算页可点开卡片 |
| `why` | string | 选完之后 NPC 说的那一句「为什么」 |
| `delay` | object? | 仅中期任务用 |
| `diy` | bool? | 标记「自己写一个做法」，不计入读数 |

### `refs` — 依据表（22 条）

```json
{ "H1": "衞生防護中心《均衡素食的要點》原文：…", "R2": "…" }
```

编号前缀是分类：`H` 卫生/营养、`R` 减排与行为、`F` 材料与衣物、`E` 教育文件、`D` 设计参数。

## 2. `data/quiz.json`

```json
{ "v": 1, "perQuestionSeconds": 20,
  "items": [ { "n": 1, "g": "A", "ref": "H1",
               "t": ["简","繁","英"],
               "o": [["A简","A繁","A英"], …4 项],
               "a": 1,
               "why": ["简","繁","英"],
               "x": [["","",""], …4 项] } ] }
```

- `g` 分组：`A` 配餐 / `B` 采购 / `C` 衣物 / `D` 取舍。
- `a` 正确项下标。
- `x[i]` 是「选了第 i 项错在哪」；正确项那一格是三个空串。
- `t/o/why/x` **全部是三元数组**，顺序恒为 `[简体, 繁體, English]`。

## 3. `data/game-i18n.json`

```json
[ { "zh": "环境负荷", "tw": "環境負荷", "en": "Environmental load" }, … ]
```

- 共 567 条；`zh` 是**匹配用的键**（页面上出现的中文字面量），必须与源文本逐字一致。
- 词条按长度优先匹配（长的先替），所以整句和片段可以共存。
- 只拿 `zh` 与 `tw` 当反查源 —— 把 `en` 也当源会把中文二次替换（踩过，见 [05-i18n.md](05-i18n.md)）。

## 4. 四本账的语义

| 代号 | 名字 | 好方向 | 结算里怎么动 |
|---|---|---|---|
| `p` | 环境负荷 | 越小越好 | 选项给出的 `fx.p` 通常是负数 |
| `s` | 营养均衡 | 越大越好 | 缺 B12 / 铁 / 钙 的选项会掉 `s` |
| `c` | 口味接受度 | 越大越好 | 跌破 `burnBelow` 触发崩盘 |
| `m` | 可用钱 | 越大越好 | 正的 `m` 会按 `saveShare` 回流成后续天数的负担 |

四条都是 0–100 的**教学映射刻度**，不是物理量。
